## 2026-03-23 - [Optimize strings iteration] **Learning:** Extensive use of `regexp.ReplaceAllString` for simple character matching and substring manipulation in hot loops leads to massive heap allocation scaling linearly with the text length, heavily pressuring the Garbage Collector. **Action:** Replace regex-based text cleaning with single-pass byte-iteration algorithms using pre-sized `strings.Builder` and batch exact-string replacements with `strings.NewReplacer` to optimize memory reuse.
## 2024-03-24 - [Replace regexp with byte filter]
**Learning:** For high-throughput text processing in hot loops (e.g. processing large manga descriptions), multiple passes with `regexp.ReplaceAllString` create massive heap allocations due to string immutability. Replacing regexes with a single-pass byte-scanning algorithm using a pre-allocated byte slice (`b := make([]byte, 0, len(strRaw))`) dramatically reduces allocations and GC pressure.
**Action:** When optimizing text filtering, avoid chaining multiple regex replacements. Instead, write a state-machine or single-pass byte filter that accumulates the desired output in a pre-allocated slice, especially for simple patterns like HTML tags or brackets.
## 2026-03-25 - [Replace in-memory slice with streaming iterator for DB rows]
**Learning:** In `cmd/calculate/helpers.go`, `getDBSimilar` was loading the entire `SIMILAR` table into a slice before returning it. For a CLI dealing with a large dataset, this creates massive memory bloat (O(N) memory complexity) and delays processing until all rows are loaded.
**Action:** Replaced the slice return with a Go 1.23 `iter.Seq`, allowing the caller to stream rows one by one directly from the database query. This drops peak memory usage to O(1) and enables the `exportSimilar` loop to process items as soon as they are yielded, significantly reducing Garbage Collection pressure.
## 2026-04-24 - [Replace DB slice allocation with an iter.Seq for text exports]
**Learning:** In `cmd/calculate/helpers.go`, `getAllGenericFromTable` loaded the entire mapping table into a slice before returning it. The CLI then iterated over the slice to flush each line into the exported text mapping. This O(N) heap allocation created huge initial memory spikes and delayed data export processing.
**Action:** Replace slice returns from database queries with Go 1.23 `iter.Seq` where possible. Combine it with `bufio.Writer` in the export functions to stream data row-by-row directly from sqlite to disk, establishing an O(1) memory pipeline that drastically cuts GC pressure and speeds up processing times.
